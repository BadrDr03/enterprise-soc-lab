# IR-009 — HTTP Data Exfiltration

## 1. Incident Summary

HTTP-based data exfiltration activity was detected on the Windows 11 endpoint `target-pc` during the SOC laboratory attack simulation.

Data exfiltration represents the stage where information collected from a compromised environment is transferred to an external destination.

HTTP and HTTPS are particularly relevant from a defensive perspective because they are commonly used for legitimate web communication. An attacker may therefore attempt to use web traffic to blend exfiltration activity with normal network traffic.

During the simulation, endpoint and network telemetry associated with the exfiltration activity was collected and analyzed through Splunk.

This incident corresponds to **UC-009 — HTTP Data Exfiltration**.

## 5. Incident Response — PICERL

### 5.1 Preparation

The SOC laboratory was prepared with:

- Sysmon endpoint monitoring;
- network connection telemetry;
- Splunk Universal Forwarder;
- centralized Splunk logging;
- network-based detection logic;
- external destination IP visibility;
- Threat Intelligence enrichment;
- SOC dashboard monitoring.

These controls provided visibility into outbound network activity generated by monitored Windows endpoints.

### 5.2 Identification

The incident was identified from network telemetry associated with the simulated HTTP exfiltration activity.

The analyst reviewed information including:

- source endpoint;
- initiating process;
- destination IP;
- destination port;
- timing of the connection;
- surrounding endpoint activity.

The event matched the detection criteria implemented in UC-009.

The investigation also considered whether the network activity followed previous collection or archive activity.

This correlation increased the security relevance of the outbound connection.

### 5.3 Containment

In a production environment, confirmed data exfiltration would require immediate containment to prevent additional information from leaving the organization.

Possible containment actions could include:

- isolating the affected endpoint;
- blocking the malicious destination at network security controls;
- terminating the responsible malicious process;
- disabling compromised accounts when appropriate;
- restricting additional outbound communication;
- identifying other systems communicating with the same destination.

Because the activity occurred intentionally inside the controlled SOC laboratory, production containment actions were not required.

### 5.4 Eradication

For a confirmed compromise, eradication would focus on identifying and removing the attacker's tooling and original access mechanism.

The investigation would include searching for:

- malicious scripts or executables;
- persistence mechanisms;
- data staging locations;
- unauthorized archive files;
- additional exfiltration tools;
- other compromised endpoints.

Any malicious artifacts discovered during the investigation would need to be removed before recovery.

No production remediation was required during the laboratory simulation.

### 5.5 Recovery

In a production environment, systems should return to normal operation only after the organization confirms that unauthorized data transfer has stopped and the attacker's access has been removed.

Recovery activities could include:

- restoring affected systems when necessary;
- resetting compromised credentials;
- validating network controls;
- confirming that suspicious outbound connections have stopped;
- increasing monitoring of affected endpoints and accounts.

In the laboratory, `target-pc` remained operational and security telemetry continued to reach Splunk.

### 5.6 Lessons Learned

Outbound HTTP communication alone is not sufficient to prove data exfiltration.

HTTP traffic is extremely common in normal environments.

The investigation becomes stronger when network activity is correlated with additional evidence such as:

- suspicious process execution;
- previous data collection;
- archive creation;
- unusual destination IP addresses;
- Threat Intelligence results;
- abnormal destination ports;
- user and host context.

This incident demonstrated the importance of analyzing exfiltration as part of a broader attack sequence rather than relying on a single network event.

## 6. Threat Intelligence Context

Public destination IP addresses observed in network telemetry can be correlated with the Threat Intelligence pipeline implemented in the SOC laboratory.

The enrichment workflow uses:

- VirusTotal;
- AbuseIPDB;
- AlienVault OTX.

The workflow is:

```text
Destination IP
      ↓
Threat Intelligence Lookup
      ↓
VirusTotal + AbuseIPDB + OTX Context
      ↓
SOC Analyst Investigation
```

Threat Intelligence can provide additional context such as reputation, abuse reports, network ownership, and threat intelligence associations.

However, Threat Intelligence results should not be treated as automatic proof that an exfiltration event is malicious.

They represent additional evidence that must be correlated with endpoint and network telemetry.

It also demonstrates the value of correlating endpoint telemetry, network activity, previous attack stages, and Threat Intelligence when investigating potential data loss.
